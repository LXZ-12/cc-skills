# jq-sonarqube-skill

SonarQube 查询参考手册。当用户提到 SonarQube、代码扫描、代码问题、Sonar 问题、代码质量时使用。

**核心能力**：问题统计、问题详情查询、规则修复建议。

---

## 配置

- 配置文件搜索路径（优先级）：`./jq-config.json` → `<skill>/jq-config.json` → `../jq-config.json`
- base_url 无需改动

```json
{
  "gitlab": {
    "token": "glpat_xxxxxxxxxxxx",
    "base_url": "https://nvwa.jiuqi.com.cn/gitlab/api/v4"
  },
  "sonarqube": {
    "token": "squ_xxxxxxxxxxxx",
    "base_url": "https://nvwa.jiuqi.com.cn/sonar/api"
  }
}
```

**Token 获取方式**：

- `gitlab.token`：GitLab → Settings → Access Tokens
- `sonarqube.token`：SonarQube → My Account → Security

## 最佳实践

### 价值与背景

| 对比维度   | 传统方式   | AI 辅助方式       |
| ---------- | ---------- | ----------------- |
| 问题查询   | 10-60 分钟 | 几十秒钟          |
| 批量修复   | 逐个处理   | 同类问题一次完成  |
| 单 PR 行数 | 几百行混杂 | 小 PR，按规则拆分 |
| 效率提升   | —          | **70%+**          |

### 核心理念：按规则批次 PR

**同一种 Sonar 规则触发的问题 → 同一种修复模式 → 一次 AI 调用解决一类问题**

推荐理由：

- AI 效率最高：同一规则修复逻辑相似，一次学习多次复用
- Review 可预期：Reviewer 知道"这个 PR 只修 S3776 复杂度"
- 回滚精准：某规则修复有问题，只回滚该 PR
- 进度可跟踪：每完成一个规则就知道解决了多少问题

### 完整工作流（8 步）

```
┌─────────────────────────────────────────────────────────────┐
│  Step 1：新建工作空间                                        │
│         在新目录拉取待修复模块的代码                          │
│         git clone https://nvwa.jiuqi.com.cn/gitlab/...      │
├─────────────────────────────────────────────────────────────┤
│  Step 2：启用 Claude Code                                   │
│         cd {模块目录} && claude                                 │
│         在该工作空间启动智能体                               │
├─────────────────────────────────────────────────────────────┤
│  Step 3：调用 Sonar Skill                                   │
│         输入 "查询 XXX 模块的 Sonar 问题"                    │
│         AI 返回问题统计（按 severity×规则分组）              │
├─────────────────────────────────────────────────────────────┤
│  Step 4：选择修复范围                                       │
│         指定要修复的规则类型                                │
│         如：java:S3776（认知复杂度）                        │
│             java:S1192（重复字面量）                        │
│             java:S2259（空指针风险）                        │
│         AI 按规则分组，生成修复批次计划                       │
├─────────────────────────────────────────────────────────────┤
│  Step 5：AI 生成修复计划                                     │
│         同规则问题 → 同一种修复模式                         │
│         生成修复方案（不改代码）                             │
├─────────────────────────────────────────────────────────────┤
│  Step 6：人工 Review 修复计划                               │
│         确认修复方案无业务逻辑变更                          │
│         确认后再执行修复                                     │
├─────────────────────────────────────────────────────────────┤
│  Step 7：执行修复 + 生成 PR                                 │
│         确认后执行代码修复                                  │
│         每个批次生成小 PR                                   │
├─────────────────────────────────────────────────────────────┤
│  Step 8：人工 Review + 合并                                 │
│         确认 diff 无问题 → 合并                              │
└─────────────────────────────────────────────────────────────┘
```

**推荐理由**：

- 新建工作空间：避免污染原有开发分支，改动清晰可追溯
- 启用智能体：CC 可直接访问本地代码，进行修复
- 调用 Skill：自动完成问题查询、分组、修复建议
- 人工 Review 兜底：必须经过人工确认才能合并

### 风险管控

| 保障措施    | 说明                            |
| ----------- | ------------------------------- |
| 人工 Review | 必须经过人工确认才能合并        |
| 可回滚      | 按规则批次 PR，问题时可精准回滚 |

### 适用场景

- 大批量 SonarQube 问题
- 按规则可分组的问题批量修复
- 版本发布前质量提升

不适用：复杂业务逻辑、跨模块重构
